# Requirements Document

## Introduction

An AI-powered Financial Stock Screening and Analytics Platform focused on the Indian Stock Market (NSE). The platform provides intelligent stock analysis through three ML models (XGBoost, TFT, Gemma 3 27B), interactive charting, financial data tables, and a custom query-based screener. Built as a static SPA (React.js + Rsbuild + Tailwind CSS) consuming a FastAPI backend that fetches real-time data from NSE India, targeting deployment on AWS Amplify with full dark/light theme support and Indian localization (₹, Crores, Lakhs).

## Glossary

- **Platform**: The AI-powered Financial Stock Screening and Analytics SPA application
- **Backend**: The FastAPI server running on localhost:8000 that fetches real-time stock data from NSE India APIs via the BSE India API library and serves ML model outputs computed from live data
- **Ticker**: An NSE stock symbol identifier (e.g., JNKINDIA, ZEEL, JAINREC)
- **Intel_Engine_Dashboard**: The main analytics view combining charting and ML scoring (TFT, XGBoost)
- **Custom_Screener**: The sub-route page allowing users to write text-based fundamental queries to filter stocks
- **Profile_Card_Grid**: The component displaying key financial ratios with color-coded threshold badges
- **Financial_Table**: TanStack Table component showing quarterly financials in Screener.in style
- **Navigation_Header**: The sticky responsive global header with search bar and theme toggle
- **Theme_Toggle**: The dark/light mode switch in the header
- **Helper_Panel**: The side panel on the Custom Screener page showing available fields and operators
- **TFT_Score**: The Macro Resilience Score (0–100) produced by the Temporal Fusion Transformer model
- **XGBoost_Rating**: The ML-generated stock rating (STRONG BUY, BUY, HOLD, SELL) with confidence float
- **Gemma_Summary**: The SEBI-style narrative summary generated by the Gemma 3 4B IT model via AWS Bedrock
- **Indian_Number_Format**: Numeric formatting using Crores and Lakhs with ₹ currency symbol
- **NSE_Data_Source**: The NSE India public APIs and BSE India API Python library used to fetch live equity data
- **Cache_Layer**: The in-memory TTL-based caching mechanism that prevents excessive requests to NSE and provides fast responses

## Requirements

### Requirement 1: Global Navigation and Search

**User Story:** As an investor, I want a persistent navigation header with a ticker search bar, so that I can quickly look up any NSE stock from any page.

#### Acceptance Criteria

1. THE Navigation_Header SHALL render as a sticky element at the top of the viewport on all pages.
2. THE Navigation_Header SHALL contain a search input that accepts Ticker symbols.
3. WHEN a user types a Ticker into the search input, THE Platform SHALL display matching suggestions from all NSE-listed equities fetched from NSE.
4. WHEN a user selects a Ticker from the search results, THE Platform SHALL navigate to the analytics view for the selected Ticker.
5. WHEN the Platform loads for the first time, THE Platform SHALL display data for the default Ticker JNKINDIA.
6. THE Navigation_Header SHALL render responsively across mobile and desktop viewport widths.

---

### Requirement 2: Dark and Light Theme

**User Story:** As a user, I want the platform to respect my system color preference and allow manual override, so that I can use the interface comfortably in any lighting condition.

#### Acceptance Criteria

1. WHEN the Platform loads for the first time, THE Platform SHALL detect the operating system color scheme preference and apply the matching theme (dark or light).
2. THE Navigation_Header SHALL contain a Theme_Toggle control.
3. WHEN a user activates the Theme_Toggle, THE Platform SHALL switch between dark and light themes immediately.
4. WHEN a user selects a theme via the Theme_Toggle, THE Platform SHALL persist the selection in localStorage.
5. WHEN the Platform loads and a theme preference exists in localStorage, THE Platform SHALL apply the persisted theme preference instead of the system preference.

---

### Requirement 3: Profile Ratios Card Grid

**User Story:** As an investor, I want to see key financial ratios at a glance with visual indicators, so that I can quickly assess a stock's valuation and profitability.

#### Acceptance Criteria

1. WHEN a Ticker is selected, THE Profile_Card_Grid SHALL display Market Cap (₹ Crores), P/E ratio, ROE percentage, ROCE percentage, and Dividend Yield percentage.
2. THE Profile_Card_Grid SHALL format all monetary values using Indian_Number_Format with the ₹ symbol.
3. THE Profile_Card_Grid SHALL display color-coded threshold badges for each metric value (green for favorable, red for unfavorable ranges).
4. THE Profile_Card_Grid SHALL render in a responsive grid layout that adapts to mobile and desktop viewports.

---

### Requirement 4: Intel Engine Dashboard - Chart

**User Story:** As an investor, I want to see historical price data with an AI-predicted future trend on a single chart, so that I can assess both past performance and projected direction.

#### Acceptance Criteria

1. WHEN a Ticker is selected, THE Intel_Engine_Dashboard SHALL render a TradingView Lightweight Charts line chart with 30 calendar days of historical OHLC closing price data.
2. WHEN generating the date axis, THE Intel_Engine_Dashboard SHALL skip Saturday and Sunday dates to reflect Indian market trading cycles.
3. THE Intel_Engine_Dashboard SHALL render responsively, adjusting chart dimensions to the available viewport width.

---

### Requirement 5: Intel Engine Dashboard - ML Scoring

**User Story:** As an investor, I want to see macro resilience and AI-based buy/sell ratings alongside the chart, so that I can make informed decisions using multiple ML signals.

#### Acceptance Criteria

1. WHEN a Ticker is selected, THE Intel_Engine_Dashboard SHALL display the TFT_Score as a gauge visualization ranging from 0 to 100 with a trend outlook label.
2. WHEN a Ticker is selected, THE Intel_Engine_Dashboard SHALL display the XGBoost_Rating badge with the rating text and confidence percentage.
3. THE Intel_Engine_Dashboard SHALL render the XGBoost_Rating badge in emerald green for STRONG BUY, green for BUY, amber for HOLD, and crimson red for SELL.
4. THE Intel_Engine_Dashboard SHALL position the chart on the left and the ML scoring widgets on the right in a split layout on desktop viewports.
5. WHEN the viewport is mobile-sized, THE Intel_Engine_Dashboard SHALL stack the chart above the ML scoring widgets vertically.

---

### Requirement 6: Advanced Financial Tables

**User Story:** As an investor, I want to view quarterly financial data in a structured, sortable table with Indian formatting, so that I can analyze revenue trends and profitability over time.

#### Acceptance Criteria

1. WHEN a Ticker is selected, THE Financial_Table SHALL display quarterly data columns for Revenue, Expenses, Operating Profit, Net Profit, and Margin percentage.
2. THE Financial_Table SHALL format all monetary values using Indian_Number_Format (Crores) with the ₹ symbol.
3. THE Financial_Table SHALL apply alternating row shading for readability.
4. THE Financial_Table SHALL right-align all numeric columns.
5. THE Financial_Table SHALL support column-based sorting via TanStack Table.
6. WHEN the viewport is mobile-sized, THE Financial_Table SHALL enable horizontal scrolling to accommodate all columns.

### Requirement 7: Gemma 3 27B Narrative Summary

**User Story:** As an investor, I want an AI-generated narrative summary of the stock's fundamentals in plain language, so that I can understand the analysis without interpreting raw numbers.

#### Acceptance Criteria

1. WHEN a Ticker is selected, THE Platform SHALL display the Gemma_Summary in a visually distinct callout widget below the Financial_Table.
2. THE Gemma_Summary widget SHALL render the SEBI-style narrative text generated by the Gemma 3 4B IT model via AWS Bedrock from the Backend response.
3. THE Gemma_Summary widget SHALL be clearly labeled as an AI-generated analysis.

### Requirement 8: Custom Screener Query Page

**User Story:** As an investor, I want to write text-based fundamental queries to filter stocks, so that I can find stocks matching my specific investment criteria.

#### Acceptance Criteria

1. THE Custom_Screener SHALL be accessible via a dedicated sub-route in the Platform navigation.
2. THE Custom_Screener SHALL provide a text input area where users can type fundamental logic queries using field names, comparison operators, and logical operators (AND, OR).
3. THE Custom_Screener SHALL display the Helper_Panel as a side panel listing all available query fields and supported operators.
4. WHEN a user submits a query, THE Custom_Screener SHALL parse the query and filter the NSE equity universe fetched from NSE.
5. WHEN query results are returned, THE Custom_Screener SHALL display results in a paginated, sortable grid.
6. THE Custom_Screener SHALL support queries combining financial metrics (Market Cap, PE) with ML outputs (AI_Rating, TFT_Score).
7. IF a user submits a syntactically invalid query, THEN THE Custom_Screener SHALL display a descriptive error message indicating the issue.

---

### Requirement 9: Real-Time NSE Data Backend

**User Story:** As an investor, I want the platform to display live stock data fetched directly from NSE India, so that I can make decisions based on current market information rather than stale or fabricated data.

#### Acceptance Criteria

1. THE Backend SHALL serve data via the route /api/screener/{ticker} for individual ticker lookups using real-time data fetched from NSE India APIs.
2. THE Backend SHALL use the BSE India API Python library with NSELive for fetching live stock quotes including lastPrice, priceInfo, metadata, and industryInfo.
3. THE Backend SHALL fetch historical OHLC data for 30 trading days from NSE India historical equity API using the stock_df function from BSE India API.
4. THE Backend SHALL fetch quarterly corporate financial results from NSE India corporate info endpoints for each requested Ticker.
5. THE Backend SHALL return a unified JSON schema per ticker containing XGBoost_Rating (rating + confidence), TFT_Score (score + trend outlook), and Gemma_Summary (narrative text) computed from real fetched data.
6. THE Backend SHALL implement a TTL-based Cache_Layer with 5-minute expiry for live quote data and 24-hour expiry for financial results and historical data.
7. THE Backend SHALL manage NSE session cookies and headers to maintain valid sessions for data fetching.
8. THE Backend SHALL serve the /api/screener/all endpoint by querying NSE index constituents (Nifty 500) and returning summary data for all constituent equities.
9. THE Backend SHALL enable CORS for requests originating from localhost:3000.
10. THE Backend SHALL run on localhost:8000 using FastAPI.
11. THE Backend SHALL load pre-trained ML model artifacts (XGBoost, TFT) at startup and run inference on real fetched data for each ticker request.
12. THE Backend SHALL use XGBoost model trained on real quarterly financials to produce a rating (STRONG BUY, BUY, HOLD, SELL) and confidence score.
13. THE Backend SHALL use TFT model with real macro data (RBI REPO rate via BSE India API RBI module and Nifty sector indices) to produce a Macro Resilience Score (0–100).
15. THE Backend SHALL use Gemma 3 4B IT model via AWS Bedrock to generate a narrative summary from real financial data.
16. IF NSE India APIs are unreachable, THEN THE Backend SHALL return a 503 Service Unavailable response with a descriptive error message indicating data source unavailability.
17. THE Backend SHALL implement rate limiting to restrict outbound requests to NSE India to avoid IP blocking.
18. THE Backend SHALL use pandas for data manipulation and aggregation of fetched NSE data.

### Requirement 10: Frontend Build and Deployment Configuration

**User Story:** As a developer, I want the frontend to build as a static SPA using Rsbuild with no server-side rendering, so that it can be deployed directly to AWS Amplify.

#### Acceptance Criteria

1. THE Platform SHALL use React.js with Rsbuild (Rspack-powered) as the build tool.
2. THE Platform SHALL produce a static dist/ directory as the build output containing all assets for deployment.
3. THE Platform SHALL use Tailwind CSS for all styling.
4. THE Platform SHALL NOT use Next.js or any server-side rendering framework.
5. THE Platform SHALL NOT require Docker, Kubernetes, or active server infrastructure for frontend deployment.
6. THE Platform SHALL organize source code into modular directories (src/components/, src/App.tsx, rsbuild.config.ts, app.py).

### Requirement 11: Indian Market Localization

**User Story:** As an Indian investor, I want all data displayed in Indian number formatting with rupee symbols, so that the platform feels native to my market context.

#### Acceptance Criteria

1. THE Platform SHALL format all monetary values using the Indian numbering system (Lakhs and Crores).
2. THE Platform SHALL prefix all monetary values with the ₹ symbol.
3. THE Platform SHALL reference NSE stock symbols and Indian market conventions throughout the interface.
4. WHEN displaying date-based trading data, THE Platform SHALL exclude weekends (Saturday and Sunday) to align with NSE trading schedules.

**User Story:** As a user, I want the platform to work well on both desktop and mobile devices, so that I can access stock analytics from any device.

2. WHEN the viewport width is below 768px, THE Platform SHALL switch multi-column layouts to single-column stacked layouts.

**User Story:** As a developer, I want fully functional, typed, modular code with no placeholders, so that the codebase is production-ready and maintainable.

#### Acceptance Criteria

1. THE Platform SHALL use TypeScript for all frontend source files.
2. THE Platform SHALL organize components into discrete, reusable modules within src/components/.
3. THE Platform SHALL contain complete implementations with no placeholder text, TODO comments, or partial code blocks.
4. THE Platform SHALL type all component props, API responses, and state using TypeScript interfaces or types.

### Requirement 14: ML Model Training Pipeline

**User Story:** As a developer, I want automated training scripts that fetch real NSE data and train all three ML models locally, so that I can produce production-ready model artifacts without manual data preparation.

#### Acceptance Criteria

1. THE Platform SHALL provide a `backend/training/` directory containing training scripts for XGBoost and TFT models.
2. THE XGBoost training script SHALL fetch quarterly financial data for Nifty 500 stocks from NSE India via BSE India API and train a multi-class classifier producing a model artifact saved as `backend/model_artifacts/xgboost_rating/model.json`.
3. THE TFT training script SHALL fetch RBI REPO rate history and Nifty sector index historical values from NSE India via BSE India API and train a PyTorch model producing a model artifact saved as `backend/model_artifacts/tft_macro/model.pt`.
5. EACH training script SHALL accept command-line arguments for hyperparameters (epochs, learning rate, batch size) with sensible defaults.
6. EACH training script SHALL log training progress (loss, accuracy/metrics per epoch) to stdout.
7. EACH training script SHALL save training metrics (final loss, validation metrics, training duration) to a JSON file alongside the model artifact.
8. THE Platform SHALL provide a `backend/training/requirements.txt` with training-specific dependencies (scikit-learn, torch, xgboost, BSE India API, pandas, numpy, matplotlib).
9. THE Platform SHALL provide a `backend/training/train_all.py` orchestrator script that runs all training scripts sequentially with default parameters.
10. EACH training script SHALL implement train/validation split (80/20) and report validation metrics.
11. THE XGBoost training script SHALL engineer features including revenue growth rate, profit margin trends, expense ratios, and quarter-over-quarter changes from raw financial data.
12. THE TFT training script SHALL engineer temporal features from historical REPO rate changes and sector index momentum indicators.
13. IF NSE India APIs are unreachable during training, THEN the training script SHALL exit with a descriptive error message and non-zero exit code.

### Requirement 15: User Authentication (Sign-Up / Sign-In)

**User Story:** As a user, I want to create an account and sign in to the platform, so that my preferences and watchlists can be saved and my usage can be tracked.

#### Acceptance Criteria

1. THE Platform SHALL provide a /signup route displaying a registration form with email and password fields.
2. THE Platform SHALL provide a /signin route displaying a login form with email and password fields.
3. WHEN a user submits the signup form with a valid email and password (minimum 8 characters), THE Backend SHALL create a new user record in DynamoDB and return a JWT access token.
4. WHEN a user submits the signin form with correct credentials, THE Backend SHALL verify the password hash and return a JWT access token.
5. THE Backend SHALL hash passwords using bcrypt before storing them in DynamoDB.
6. THE Backend SHALL issue JWT tokens with a 24-hour expiration containing the user's email and user ID as claims.
7. THE Platform SHALL store the JWT token in localStorage upon successful signup or signin.
8. WHEN a JWT token exists in localStorage, THE Navigation_Header SHALL display the user's email and a Logout button instead of Sign In/Sign Up links.
9. WHEN the user clicks Logout, THE Platform SHALL remove the JWT token from localStorage and redirect to the home page.
10. THE Backend SHALL provide a POST /api/auth/signup endpoint accepting email and password in JSON body.
11. THE Backend SHALL provide a POST /api/auth/signin endpoint accepting email and password in JSON body.
12. THE Backend SHALL provide a GET /api/auth/me endpoint that validates the JWT from the Authorization header and returns user profile data.
13. IF a user attempts to sign up with an email that already exists, THEN THE Backend SHALL return a 409 Conflict response with a descriptive error message.
14. IF a user submits invalid credentials on signin, THEN THE Backend SHALL return a 401 Unauthorized response.
15. THE Platform SHALL validate email format and password length on the client side before submitting to the backend.
16. THE signup and signin forms SHALL display error messages returned from the backend inline below the form fields.
